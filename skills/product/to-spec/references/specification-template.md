# Specification Template

```markdown
## Problem Statement

Describe the problem from the user's perspective.

## Solution

Describe the agreed solution from the user's perspective.

## User Stories

List the user stories extensively in this form:

1. As a <actor>, I want <capability>, so that <benefit>.

## Implementation Decisions

Record durable decisions about modules, interfaces, architecture, schemas, API
contracts, and interactions. Avoid volatile file paths and working code.

## Testing Decisions

Describe the observable behavior to test, the chosen behavioral seams, and
relevant testing precedent in the codebase. Prefer external behavior over
implementation details.

## Out of Scope

Record explicit exclusions and intentional deviations so later agents do not
reintroduce them.

## Open Questions

Record only unresolved facts that materially affect the specification. Omit
this section when none remain.

## Further Notes

Capture constraints or context that cannot be inferred from the code.
```
