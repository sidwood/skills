# Commit Message

Write the commit message using this template:

```
Capitalized, short (50 chars or less) summary

More detailed explanatory text, if necessary. Wrap it to about 72
characters or so. In some contexts, the first line is treated as the
subject of an email and the rest of the text as the body. The blank
line separating the summary from the body is critical (unless you omit
the body entirely); tools like rebase can get confused if you run the
two together.

Write your commit message in the imperative: "Fix bug" and not "Fixed
bug" or "Fixes bug." This convention matches up with commit messages
generated by commands like git merge and git revert.

Further paragraphs come after blank lines.

- Bullet points are okay, too

- Typically a hyphen or asterisk is used for the bullet, followed by a
  single space, with blank lines in between, but conventions vary here

- Use a hanging indent
```

## Rules

1. **Subject line**: Capitalize the first word. Keep to 50 characters or less.
2. **Blank line**: Always separate subject from body with a blank line. Omit the body entirely if the change is self-explanatory.
3. **Imperative mood**: Write the subject as a command — "Add feature", "Fix bug", "Remove deprecated method" — not "Added", "Fixes", or "Removing".
4. **Body wrap at 72 characters**: Hard-wrap the body at 72 characters so `git log` displays cleanly on 80-column terminals.
5. **Explain why, not what**: The diff shows what changed. Use the body to explain *why* the change was made and any non-obvious consequences.
6. **Bullet points**: Use a hyphen or asterisk followed by a single space. Separate bullets with blank lines. Use a hanging indent for wrapped lines.
